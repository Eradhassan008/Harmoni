# Harmoni - Steering rules

These rules were applied to every change in this project. Follow them for all
future work.

## Stack
- Python + Streamlit. Use the Python already installed on the machine.
- Dependencies: streamlit, pandas, plotly, python-dotenv, reportlab.

## Ownership
- Edit only your own file(s). `app.py` (UI), `ai.py` (AI adapter), and
  `analytics.py` (metrics/exports) have separate owners.
- Do not refactor working code you do not own.

## Medical safety
- **Never add, change, or guess a medication dose or frequency.** If a dose or
  frequency is unclear, mark the item "Needs review" and let the patient fix it.
- **No diagnosis and no treatment advice.** No diet or weight-loss advice.
- Keep the footer on every page: "Not medical advice. Always follow your care
  team's guidance."

## Honesty of outputs
- Label every output by its true source:
  - "Your records" - the patient's own logged data.
  - "Detected automatically from your records (rule-based, not AI)" - computed
    in code, not by a model.
  - "AI-generated (live model)" - ONLY text ai.call_ai returns in live mode.
  - "Sample output - not generated by live AI" - ai.call_ai demo-mode text.
- Keep the patient's original wording; do not paraphrase instructions.

## Data
- Synthetic demo data only (fictional patient "Aisha"). No real medical data.
- The JSON backup is demo storage, clearly labelled "not secure medical
  storage".

## Secrets
- Secrets go in `.env` or `.streamlit/secrets.toml`. **Never commit secrets** -
  both are in `.gitignore`. No provider, endpoint, model name, or credential is
  hard-coded.

## Git
- Never build on `main`. Work on a feature branch and open pull requests.
- Run a smoke test (`streamlit run app.py`) before committing UI changes.
